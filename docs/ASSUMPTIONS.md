1. Authentication is simulated using simple login APIs and plain password storage for academic demo purpose.
2. Admin user is pre-created in seed data.
3. H2 in-memory database is used for easy demonstration.
4. Minimum 200 equipment records are generated during backend startup.
5. Students and staff can request equipment.
6. Admin can approve, reject, and mark requests as returned.
7. Quantity is reduced after approval and increased after return.
8. The system is designed as a prototype for assignment demonstration.
